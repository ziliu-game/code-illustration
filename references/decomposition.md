# 拆字会意：字义本来就是部件意义的合

会意字的图不用"找物件"，**部件就是物件**：日+月 = 明，人依木 = 休，手搭目 = 看，宀下火 = 灾，三木 = 森。这一层比配符号更值，因为它同时讲对了**字形**和**字义**——对识字场景，这是最理想的一种配图。

## 部件不够就先补件

会意字卡住，十次里九次是缺部件，不是缺想法。补件有三条便宜路：

1. **先用参数，不画新图**。`A.person` 已经带 `dress:true`（裙）、`hair:'bun'`（发髻）、`child:true`（大头小孩），所以"女""子"两个部件不用新画，直接 `['person', {dress:true, hair:'bun'}]`、`['person', {child:true}]`。
2. **缺的部件真画**。`豕` 没有替代物，画 `A.pig`（椭圆身＋小头＋猪鼻＋折耳＋卷尾），`家` 才立得住。
3. **抽象部件借动作**。`力` 没有可画之物，用"人举石头"（`strengthArt()`）——这是隐喻，不是字形；所以它进 `WORDS`（词级），不进 `HUI`（字级）。

## 三套版式

```js
const HUI = {
  明: { parts: ['sun', 'moon'], lay: 'side' },
  森: { parts: ['tree', 'tree', 'tree'], lay: 'tri' },
  看: { parts: ['hand', 'eye'], lay: 'stack' }
};
```

- `side`：左右结构。前件 66%、后件 54%，后件压在前件身后，共一条地平线——**左右结构必须让后件"退后"**，否则两个并排的图标读成"两个东西"，不是"一个字"。
- `stack`：上下结构。上件 42%、下件 52%，上件落在 y≈6，下件踩地平线。
- `tri`：三件结构。下二上各 40%/34%，顶件居中。

## 只有"词义 = 字形义"的词才许启用

`HUI_WORDS` 是逐个登记、逐个审稿的白名单：

```js
const HUI_WORDS = {
  观众: '众', 群众: '众', 大众: '众',     // 人多成众
  灾难: '灾', 灾害: '灾',                 // 火灾即灾
  渔民: '渔', 渔夫: '渔', 渔翁: '渔',     // 水中有鱼
  分明: '明', 明朗: '明', 明显: '明'      // 日月为明
};
```

不是"词里含这个字"就都能画。判据只有一条：**把这张图念出来，念的是不是这个词**。

- `观众/群众/大众` → 三人成众 ✓（词义就是人多）
- `灾难/灾害` → 屋下失火 ✓
- `分明/明朗/明显` → 日月为明 ✓
- `说明` ✗（是动词"讲清楚"，日月念不出"讲"）
- `从来` ✗（`从`是"跟随"，`从来`是"一直"）
- `沉思/品德/品尝` ✗（会意部件对不上词义）
- `蝉鸣/轰鸣` ✗（画成"口+鸟"，蝉与机器都不是鸟）

## 两个必须记住的坑

1. **字形对 ≠ 词义对**。`晶莹` 按字形是三日（晶），但画出来是"三个太阳"，念出来是"大晴天"，不是晶莹——这一条已撤掉。字形只是必要条件。
2. **部件必须有图元**。`好`（女+子）、`男`（田+力）、`家`（宀+豕）都拆得对，但库里没有女、子、力、豕的图元，硬凑会用"人+小孩"画成"母子"，更错。缺部件就先补图元，再启用会意。

## 加一个会意字

1. 查部件是否都有图元（`A` 的键名）；缺就先补图元。
2. 判结构：左右 `side` / 上下 `stack` / 三件 `tri`；合体字里"主体在前"的（`岩`、`灾`）加 `front: 1`。
3. 写进 `HUI`，再挑词写进 `HUI_WORDS`（只挑词义 = 字形义的）。
4. 渲染后缩到 76px，问自己："不给我看词牌，我念得出这个字吗？"念不出就回退。
5. 跑 `node scripts/demo.js decomp` 与 `node scripts/validate.js --batch`。
